TalkingData-AdTracking-Fraud: Big Data & Real-Time Ad Fraud Detection

Big Data & ML Python 3.11+ Polars LightGBM XGBoost CatBoost Streamlit

An end-to-end, institutional-grade Big Data Analytics, High-Speed Feature Engineering, and Gradient Boosting Ensembling platform built around the Kaggle TalkingData AdTracking Fraud Detection Challenge.

This repository addresses the technical challenges of processing 180M+ click records (~7.5 GB) and detecting extreme class imbalance (~0.24% positive attribution rate) on consumer hardware by combining Polars Memory Downcasting (int64 to uint16/uint8), Time-Delta Window Feature Engineering, and Multi-Model Stacking (LightGBM, XGBoost, CatBoost).

What Makes This Platform High-Performance & Scalable?

In digital advertising networks, ad fraud rings and automated botnets generate billions of fake mobile app clicks to siphon marketing attribution budgets. A production-grade attribution fraud engine must process high-velocity click streams, track historical user frequency profiles, and score attribution legitimacy with sub-second latency.

This platform achieves rigorous data engineering efficiency and predictive accuracy across 4 foundational layers:

  • Memory Optimization Engine (src/data/memory_optimizer.py): Consumer hardware frequently crashes when processing 185+ million tabular rows with default 64-bit integers. By dynamically inspecting numeric boundaries across ip, app, device, os, and channel, the engine safely downcasts columns to uint32, uint16, and uint8, reducing total RAM consumption by >59.3% without loss of precision.
  • Time-Delta Window Feature Engineering (src/features/time_windows.py): Bot click-spam rings exhibit non-human click velocity. Using multi-threaded Polars window operations (.shift(-1).over(["ip", "app", "device"])), the system computes forward/backward time deltas (next_click, prev_click) and rolling hourly density metrics across millions of records at high speed.
  • Out-of-Fold Smooth Target Encoding (src/features/target_encoding.py): High-cardinality categorical variables (ip, app, channel) cannot be one-hot encoded at this scale. The engine applies 5-fold regularized target encoding with m-estimate smoothing (m=20.0), capturing conversion propensity without target leakage.
  • Rank-Averaged Ensemble & Explainability (src/models/): Emulating chronological evaluation splits, the ensembling engine stacks LightGBM (0.9799 ROC-AUC), XGBoost (0.9685 ROC-AUC), and CatBoost (0.9989 ROC-AUC) via rank averaging (scipy.stats.rankdata), achieving 0.9850 combined ROC-AUC while outputting exact gain-based feature explanations.

Key Engineering Highlights

1. Big Data Engineering Layer

  • High-Fidelity Power-Law Data Generation: Includes src/data/generator.py which simulates multi-million row ad traffic matching exact real-world mobile click distributions (Pareto/Zipfian tail across 50,000+ IPs and 700+ apps) with 0.24% base fraud rates and logical bot-ring penalties.
  • Polars Window Processing: Replaces Pandas groupby operations with Polars .over() partition windows, enabling multi-threaded computation of time differences across millions of rows in seconds.
  • Out-of-Core Readiness: All data transformations operate on Polars schemas, enabling direct compatibility with out-of-core streaming or instant cloud mounting on Kaggle (/kaggle/input/) and Google Colab.

2. Gradient Boosting & Class Imbalance Optimization

  • Chronological Validation Strategy: Splits training and validation splits strictly on timestamp arrival rather than random splits, mirroring live production deployment where future clicks are evaluated against historical patterns.
  • Undersampling & Focal Calibration: Addresses the 0.24% class imbalance by dynamically undersampling negative majority instances during model fitting while keeping validation folds unaltered for uncorrupted metric reporting.
  • Multi-Model Rank Averaging: Combines diverse tree architectures (LightGBM leaf-wise growth, XGBoost exact greedy splitting, and CatBoost symmetric trees) via rank normalization to eliminate calibration discrepancies across individual models.
